# 灵足时代 RobStride 电机驱动

`robstride_motor.h/.cpp` 实现 EL05 与 RS00～RS06 的**私有扩展帧协议**。
公开入口为 `Class_RobStride_Motor`，使用 Classic CAN、1 Mbps、29 位 ID、8 字节数据。
五参数运控属于私有协议类型 1，不是另一个标准帧 MIT 协议。
本驱动不实现 CANopen、标准帧 MIT 或固件升级。

依据：[厂商 EL05 手册（251112）](https://files.seeedstudio.com/products/RobStride/Product%20Literature/EL05/EL05User%20Manual251112.pdf)，
[厂商 SDK 协议与型号量程](https://github.com/RobStride/EDULITE_A3/blob/main/el_a3_sdk/docs/%E7%94%B5%E6%9C%BA%E9%80%9A%E4%BF%A1%E5%8D%8F%E8%AE%AE%E6%B1%87%E6%80%BB.md)。
SDK 汇总中的部分报文示意把 ID 和数据连在一起，实际按 29 位 ID 与 8 字节载荷分别编码。

## 集成边界

源码已加入根 CMake，现有 100 Hz `StatusTask` 调用 `ServiceAll()`，不新增任务。
驱动当前未绑定具体机构，由应用显式创建静态实例并配置总线、节点、主机、型号和方向。
通过 CMake 的 `H7_CAN1_EXTENDED`、`H7_CAN2_EXTENDED`、`H7_CAN3_EXTENDED` 逐路启用扩展帧（默认均为 `OFF`），
未启用扩展帧的总线在 `Init()` 时直接返回 `false`。
底层使用 `BSP_CAN_RegisterMaskedCallback()` 按源节点掩码 `0x0000FF00` 单条注册接收，
实例须为静态生命周期且不可复制，注册失败不能销毁或换节点重试；底层不提供掩码回调和 Daemon 注销接口。
`Init()` 不发送任何命令，应用必须显式请求配置。

## 控制与单位

| 接口 | 功能与约束 |
| --- | --- |
| Init(config) | 保存总线、节点、主机、型号、方向与位置映射范围，注册接收与 Daemon |
| ConfigureSpeed(i,t,a,timeout,position_speed) | 请求失能准备、反馈上报、模式与限值回读；不会使能 |
| RequestControlMode(mode) | 安全切换原生速度/CSP，完成前 `control_configured=false` |
| QueryIdentity() | 类型 0；回复 UID 进入快照，不视为运动反馈在线 |
| SetActiveReporting(bool) | 类型 24；建议只读接入时开启上报，不使能运动 |
| RequestEnabled(bool) | 类型 3/4；`true` 仅是入队成功，`ready` 等待后续有效反馈 |
| SetMode(mode) | 失能后写 `run_mode`，服务任务回读确认；等待期间不允许使能 |
| SetMotion(p,v,kp,kd,t) | 运控模式五参数：rad、rad/s、协议增益、N·m |
| SetTorque(t) | 运控模式，位置/速度/增益全零，仅前馈力矩 |
| SetSpeed(v) / SetCurrent(i) | 原生速度/电流模式，rad/s、协议 Iq 电流 A |
| SetPosition(p) | PP/CSP 原生位置模式，输出端多圈 rad |
| SetCurrentLimit(i) / SetTorqueLimit(t) | 失能时配置电流/转矩限制 |
| SetSpeedLimit(v) | 失能且模式确认后配置 PP 或 CSP 对应速度参数 |
| SetAcceleration(a) | 失能且模式确认后配置 PP 或速度模式加速度 rad/s² |
| SetCanTimeoutMs(ms) | 失能时配置电机侧 CAN 超时；0 为关闭，需核对固件支持 |
| ClearError() | 失能时发类型 4、`data[0]=1`；不会伪造清错成功 |
| SetZeroPosition() | 失能且确认运控/CSP 模式；位置等待真实反馈，不预先清零 |
| ReadParameter(index) | 类型 17；最近回复的 `index/bits/ok/sequence` 进入快照 |
| WriteParameter(index,bits) | 失能时原始参数写入，调用方负责类型、权限和范围 |
| SaveParameters() | 失能时类型 22 显式保存；普通参数写入不自动持久化 |

原始参数接口禁止写模式和运动目标，避免绕过控制许可。浮点参数以 32 位 IEEE754 位型
传入；参数索引、参数值为小端，运控与状态的 16 位物理量为大端。
型号选择仅决定量程，不会识别或更改实际电机型号。
NaN/Inf 和负增益拒绝；运控目标/增益、速度、电流按型号量程限幅；限值配置越界返回 `false`。
PP/CSP 位置使用有限 float 原值，不受运控 `±12.57 rad` 映射范围限制。

EL05 映射范围为位置 `±12.57 rad`、速度 `±50 rad/s`、力矩 `±6 N·m`、Kp `0～500`、Kd `0～5`，
电流参数上限 `11 A`。这些是协议范围，不代表允许持续运行到该值。
旧 RS 固件存在 `±12.5 rad` 位置映射，调用方用 `position_max_rad` 明确配置。
所有运动量均为输出端，不再除 9:1 等减速比。
`reverse` 同时作用于位置、速度、电流与力矩指令及运动反馈，不影响正数限制和增益。
类型 2 位置保留协议映射值，不凭相邻反馈猜多圈。已请求配置的实例由 `ServiceAll()` 按 100 Hz 读取 `0x7019`，
在快照提供 `total_position_rad` 与 `position_valid`；参数回复超过 100 ms 视为位置不可用，不冒充类型 2 在线。

## 生命周期与安全语义

推荐顺序为：`Init` → 开启上报/收到状态 → `RequestEnabled(false)` → 反馈确认 `state=0` →
`SetMode` → 参数回读确认 → 配置限流、限速与电机侧超时 → `RequestEnabled(true)` →
反馈确认 `ready` → 提交当前目标。不要先等待 `ready` 再请求使能。

`SetMode` 返回成功只代表写入入队。`ServiceAll` 在下一周期即首次尝试回读 `0x7005`，未确认则每 100 ms 重试，
只在匹配节点、主机、索引、成功标志与请求模式均匹配时确认；1 s 未确认结束等待且保持未确认，调用方可重新请求。
参数值改变、设备复位等外部操作仍须由设备唯一所有者协调，不能并接另一控制主机修改模式。

只有总线、源节点、目标主机与 8 字节长度合法的类型 2 状态帧刷新 Daemon；类型 21 故障帧允许目标主机或 `0xFE` 广播。
快照在短临界区内复制，`online` 为最近 100 ms 有合法运动反馈，同时暴露 `configuration_step` 便于诊断配置阶段。
`ready` 同时要求在线、请求使能、反馈运行状态为 2、无故障、模式已确认且无待提交停机。
快照保存类型 2 故障位和类型 21 详细故障/预警；类型 2 无故障不会自动抹掉类型 21 详细故障码，仅在显式 `ClearError()` 后收到无故障类型 2 反馈或新类型 21 零故障码时清零。
离线或故障撤销使能许可，`ServiceAll` 提交停机并补交失败项；恢复后需上层重新请求，
不自动重放运动目标。离线还会撤销模式确认，恢复后重新确认模式。
驱动不自动清错。预警码单独报告，不等同于已发生故障。

全部发送使用非阻塞 FIFO 且均在临界区外调用 `CAN_Tx_Submit()`，避免在关全局中断时调用 FreeRTOS API；调用方必须检查 `bool`。连续控制被拒绝时不会隐式保存重试，
应停止相应业务并提交失能；失能提交失败由 `ServiceAll` 重试。
使能提交失败返回 `false`，由调用方重新请求；成功请求在在线、无故障且无待停机时由服务任务补发到运行状态确认（补发前同步预刷安全零速或当前多圈位置）。
相同使能请求不反复发送，相同失能请求仅在停机尚未入队时重试。
运控力矩会改变完整 CAN ID，而原生目标和配置参数又共享类型 18 ID，所以不能直接套用现有
按完整 ID 保存的周期槽。FIFO 保证已接受目标先于后续停机，停机后无旧周期目标覆盖。

目前每条总线每 1 ms 至多取出一条 FIFO 消息，多电机和管理指令共享该预算。
控制频率须留出带宽，禁止靠排满队列维持运行；停机也会受已排队报文和硬件拥塞影响。
MCU 掉电或 CAN 物理断路时软件停机不能到达电机，因此必须按固件能力配置并验证电机侧超时保护。
所有非 ISR 操作由唯一应用任务调用；`StatusTask` 与 ISR 的共享状态由驱动短临界区保护。

## 应用控制准备

`ConfigureSpeed` 接受参数后，`ServiceAll` 依次提交停机、开启上报、等待失能、切模式回读、
限流、限矩、速度加速度或 CSP 限速、CAN 超时。整型超时要求位型一致，浮点限制按 `1e-3` 容差回读确认后进入下一阶段。
请求成功不等于准备完成，以快照 `control_configured` 为准。原生速度模式为初始模式；
`RequestControlMode` 在速度和 CSP 间切换，保留应用提供的限制值，先提交停机再重新确认目标模式与对应模式限制（在线且基础参数已确认时跳过重复的全局限流/限矩/超时写入，掉线或故障后仍执行完整 8 步重配）。
等待上报期间每秒重试启动步骤，写入未确认每 500 ms 重试，不进行阻塞等待或自动保存。
失能／配置期间每 50 ms 发送类型 4 停止帧，读取其类型 2 状态回复；
兼容未维持类型 24 主动上报的固件，不通过使能维持在线，也不将参数回复当作运动状态。
速度使能前先写 0，CSP 使能前先写当前多圈位置，以免执行上次保留的目标。
掉线后重做配置，运行状态意外退出也撤销旧模式确认；不自动恢复旧输出请求。

## 验证

已在开发阶段通过主机协议/状态机夹具验证扩展帧开关隔离、运控/速度/CSP 模式切换、
8 步异步配置回读、原生多圈位置、方向反转、Type 21 故障保护及显式清错，并通过当前板型固件构建。
主机模拟和编译不代表已验收实机位置环增益、停止距离、限流或电机侧超时行为。
